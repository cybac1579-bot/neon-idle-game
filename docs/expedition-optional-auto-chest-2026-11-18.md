# 《네온 방치단》 유물 상자 선택형 자동 개봉 (2026-11-18)

## 해결하려는 실제 플레이 문제
사용자는 《환생용병단》에서 영구 유물 수집은 즐겼지만, 상자 수령 등 잦은 개입 때문에 시간을 내기 어려워했다. 독립 원정 원형의 기존 `자동 구매`는 병력·훈련·보급을 자동 구매해도 **유물 상자는 반드시 직접 개봉해야만 영구 강화가 적용**됐다. 매 5거리 획득한 상자를 누락하면 수집 성장이 멈춘 듯 보이며, 저접촉/오프라인 원정 목표와 충돌했다.

## 실제 구현
- `site/expedition-engine.js`: 독립 `autoChest: {enabled:false, elapsed:0, opened:0}` 설정. `setAutoChest(state, enabled)`는 **명시적 참/거짓**만 허용한다.
- 유저가 **유물 도감 탭**에서 `상자 자동 개봉 켜기`를 누른 이후에만 60초마다 **이미 획득한** 상자를 최대 20개 FIFO로 개봉한다. 상자가 없는 동안 유물 추첨조차 실행하지 않는다.
- 실제 개봉은 기존 `openChestBatch` → `openChest` 경로만 사용. 수동과 **동일한 출처 거리·유물 등장 확률·특정 거리 최초 발견 보장·중복 상한·난수 소비**를 사용한다. 무료 상자 생성이나 추가 보너스 없음.
- 기존 `tick` 안에 편입되어 foreground 및 최대 2시간의 offline 정산에서 동일하게 동작한다. 오프라인 중에 자동 수집한 결과는 도감의 소장 유물과 최근 기록에 반영되며, 자동 개봉에 대한 별도 팝업을 강제하지 않는다.
- `site/expedition-app.js`의 사용자가 누르는 도감 전용 토글은 즉시 저장됨. `site/expedition-ui.js`는 켜짐/꺼짐, 60초 간격, 이번 탐사 자동 개봉 개수를 표시한다. `site/expedition-ui.css`는 360px 세로에서 긴 안내를 줄바꿈한다.
- 자동 구매와 자동 개봉은 **서로 독립된 옵트인 설정**이다. 자동으로 귀환·코어 투자·특성 변경을 하지 않는다. 종전 수동 1개/최대20개 개봉은 켜짐 여부와 무관하게 여전히 가능하다.
- 기존 저장의 `autoChest` 누락/위조된 설정은 **기본 꺼짐**. 저장 키/스키마 VERSION=1은 그대로. 정식 코드를 자동화한 것이 아니라 독립 테스트 원형에만 추가했다. 환생 후 선택한 켜짐 여부만 보존, 해당 탐사의 개봉 수는 0으로 초기화.

## 검증
- `tests/expedition-auto-chest.test.cjs`: 신규 **10개 회귀 테스트**. 새/구 저장 기본 꺼짐, 잘못된 값 거부, 59→60초 동작, 동일 60초 수동 개봉 대비 RNG·재화·유물·깊이 FIFO 일치, 20개 상한, 비활성 2시간 오프라인 보관, 활성 오프라인/전면 동등성, 토글 초기화, 귀환 후 선택 보존·코어 무단 투자 없음, 수동 버튼 유지.
- `tests/expedition.test.cjs`에 테스트 연결 → 기존 저장 CI에 통합.
- `tests/expedition-browser.test.cjs`: 도감에서 기본 OFF→ON, 실제 로컬 저장 확인, 새로고침 후 ON 유지, OFF 전환, 360/390/412px 가로 넘침 검증.
- 검증 결과는 자동화 ON과 OFF의 플레이 결과가 같다는 의미는 아님. ON을 고르면 상자를 더 일찍 열어 영구 효과를 누리므로 전진 속도가 달라질 수 있다. 기존 밸런스 지표는 자동화 OFF 기준으로 그대로 비교하고, ON 전략은 별도로 평가한다.
