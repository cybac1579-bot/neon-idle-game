# 《네온 방치단》 60거리 보스 후반전 연출·저장 복원·자동 구매 비교 (2026-11-18)

## 이번 작업에서 우선 해결한 실제 오류
55거리 신규 영구 유물 「추격 신호기」가 60거리 보스의 절반 체력부터 피해량 +60%를 적용하고, 첫 발동에는 `battleEvent.type='pursuit'` 신호를 출력한다. 그러나 게임 엔진의 기존 저장 복원 코드가 허용 전투 이벤트 목록에 `pursuit`를 등록하지 않아, **신호가 출력된 직후 저장했다가 재접속하면 의미 없는 기본 타격 `hit`으로 바뀌는 오류**가 있었다. 실제 강화 효과 자체는 유지되었으나 연출 기록과 표현이 잘못됐다.

- `site/expedition-engine.js`: `normalize()`이 `pursuit` 전투 신호를 원래 타입·순서 번호로 복원. 기존 `neon_expedition_prototype_v1` 키/저장 버전 변경 없음.
- `site/expedition-field.js`: 이미 존재하는 전투장 경고 띠(`enemyIntent`)가 보스 후반부 `pursuitBoost(s)>1`인 동안 **추격 신호기 후반전 화력 +60%**를 표시. 적의 실제 조준·돌격 경고가 있을 때는 위험 신호를 우선 표시하고, 경고가 없을 때 후반전 상태로 돌아온다. 전투장에 별도 버튼, 자원 통계, HUD 칸을 추가하지 않음.
- `tests/expedition-stage55-pursuit.test.cjs`: 저장 직후 전투 이벤트의 원래 타입 `pursuit`와 시퀀스 번호가 보존되는지 명시적으로 검사. 기존 8개 테스트 유지.
- `tests/expedition-browser.test.cjs`: 동일 보스를 360/390/412px 화면에서 합성된 전투 상태로 재현해 추격 신호기 발동 시각 효과, 저장 복원 타입, 동일한 후반전 안내의 유지 확인.

## 오래 걸리는 보스전 원인·대안 실험
세 번째 원정에서 60거리 보스가 약 9~15분 걸리는 현상은 유물 개봉 시각, 구매 정책, 영구 수집·전투 역할 차이의 복합 문제. 단순히 보스 체력을 다시 줄이지 않도록 **기존 시스템의 선택에 따른 차이**를 우선 비교했다.

1. **60거리 보스 교전 3분 뒤 자동 구매를 훈련·용병 중 구매 가능한 쪽으로 바꾸는 반사실 실험**: 동일 3시드 × 수동/자동 상자 2개 조건, 균형 구매만 기준. 수동 상자 조건의 2개에서는 17~30초 단축됐지만 나머지 4개는 변화 없음. `balanced` 또는 `adaptive`의 사용자 선택 의미를 바꾸기에는 근거가 약하므로 **실제 자동 구매 코드에는 반영하지 않음**.
2. **세 번째 원정에서 다른 기존 구매 모드 선택**: 첫 두 원정을 동일한 균형 구매로 완료하고, 동일한 세 번째 원정 저장에서 균형·유동·훈련 전용·소집 전용·경제 전용·장기 저축을 비교. 한 시드에서는 유동형이 오히려 느렸고 다른 두 시드에서는 약 13~21분의 전체 원정 시간을 줄였다. 단일 항목 전용 모드를 끝까지 방치하면 심층에서 진행이 막히는 예도 확인. 따라서 특정 모드가 항상 최적이라고 게임에서 강제 권장하거나 자동 변경하지 않음.
3. **별도 교전 통계 HUD 추가 여부**: 현재 귀환 상세에는 이미 현재 적과 싸운 시간, 남은 HP, 그 전투 중 자동 구매 횟수 및 기존 최장 교전 기록이 제공된다. 메인/전투 HUD 과밀 방지를 위해 중복 UI를 추가하지 않고, 실제 전술 변화를 알아볼 수 있는 기존 좁은 경고 영역만 재사용했다.

## 검증
- 저장 버전 및 기존 보스 체력/적 공격력·자원 보상/유물 드롭률/코어 가격/자동 구매 정책 변경 없음.
- 신규 후반전 복원과 기존 55거리 추격 신호 회귀 **8개**, 심층 방벽 연계 **8개**, 45→50→60거리 장기 진행 **12개** 경로를 최신 공유 엔진에서 직접 재실행해 통과.
- 전체 GitHub CI의 저장·첫 귀환·3회 원정·모바일 브라우저 검사 결과를 커밋별 확인하여 보고. GitHub Actions에서는 중첩된 브랜치 커밋으로 브라우저 실행이 취소·대기할 수 있어 완료와 대기를 혼동하지 않음.

## 남은 판단
약 15분 걸리는 일부 느린 60거리 보스는 여전히 문제가 될 수 있다. 전투 중 유의미한 선택·새로운 수집 목표가 충분한지 **실제 사용자가 플레이한 데이터와 체감**으로 검증하고, 결함이 확인되면 기존 자동 구매·코어·영구 유물 규칙을 보존한 소규모 개선을 우선한다.

유일한 공동 개발 브랜치 `integration/reconcile-main-redesign-20261114`; `main`과 기존 게임 및 원형 저장 키는 보호한다.

## 후속 수정: 브라우저 CI 저장 경합 및 전투 신호 복원 (2026-11-18)
- 구 모바일 CI 실행 `44240890979`에서 390px 구간의 **유물 전체 수집 테스트**가 실패했다. 실제 화면이 `현재 원형의 신규 종류 없음` 대신 14종 미수집을 표시했는데, 원인은 테스트가 **열려 있는 앱의 localStorage만 수정한 직후 reload**하여 페이지 종료 저장이 가짜 완료 데이터를 덮어쓴 **테스트 픽스처 경합**이었다. 게임의 유물 획득률·세이브 포맷 문제로 오판하지 않는다.
