# 《네온 방치단》 신규 탐사 — 첫 원정 격파 시각 계측 (2026-11-18)

## 목적
첫 환생 시점을 강제로 60분에 맞추기 전에 실제 격파 구간을 측정. 기존 60초 간격 플레이 로그는 5·10거리 보스 격파 시점을 놓칠 수 있어 별도 경과 기록을 도입함.

## 이번 구현
- 엔진 site/expedition-engine.js: 5/10/15/20/25/30/35/50/75/100 거리의 **실제 적 격파 시각**을 현재 탐사 runMilestones에 0.1초 단위로 저장.
- 적격성 검증: 저장 불러오기 시 미지의 거리 키, 음수, 비정상 시간을 버림. 과거 데이터에 없던 기록은 창작하지 않음.
- 귀환: 최근 5회 runHistory의 각 항목에 milestones를 보존, 신규 탐사는 빈 기록으로 시작.
- 화면: 별도 **도감 → 탐사 기록**에 5·10·15·25·35거리 이번 탐사와 직전 탐사 격파 시간 비교. 메인/전투 화면 수치 증설 없음.
- 사용자 요청으로 생성하는 로컬 JSON 내보내기에 currentRun.milestoneClears 추가. 자동 전송 없음.
- tests/expedition-milestones.test.cjs: 새 회귀 테스트 7개(겹침 방지, 실전 적 격파, 60초 간격 독립성, 저장 복구, 귀환 기록, 오프라인 동등성 등). 기존 CI에 연결.
- tests/expedition-first-run-milestone-audit.cjs: 5개 정책 × 3개 시드, 30분 저조작 엔진 재현 시뮬레이터. 기존 CI 실행 경로에 연결.

## 판단
- 균형 자동 구매에서 10거리 보스는 1분 전후, 35거리 보스는 약 23~28분 후. 첫 귀환 가능 시점을 시간만 늘리면 전투·보급·수집의 빈 구간이 채워지지 않음.
- 특히 균형 자동의 30→35거리만도 약 10~13분. 다음 단계에서 이 구간의 구매/유물/전투 피드백을 분석해야 함.
- 훈련/보급 단일 모드는 성장에 필요한 다른 종류의 투자가 없으므로 더 빨리 정체됨. 선택 루트의 시간을 억지로 같게 만들지 않음.
- 이전 60분 첫 환생 목표는 새 참조 구조에 그대로 강요하지 않고, 플레이 밀도와 사용자의 재미 평가를 거쳐 재검토.
- 이번 회차에서 적 체력, 강화 비용, 자동 구매 주기, 환생 보상, 계승 규칙을 임의 변경하지 않음.
