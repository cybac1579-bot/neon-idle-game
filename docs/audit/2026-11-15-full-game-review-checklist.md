### 2단계 상세 문제/개선 후보

- **AUD-06 (콘텐츠 공백·보통~큼):** 실제 `SKILLS`는 **3종**(`overload`, `chain`, `bountySkill`)인데 스킬 슬롯은 최대 5개이고 UI에는 '보유 x/4'로 표시. **5칸 모두 활용하는 선택지 자체가 현재 없음**. 크래시 버그가 아니라 스킬 중심 성장 콘텐츠 부족이며 5·9단계에서 실제 체감 영향 판정. 주석에도 '스킬 4종'으로 적혀 있어 문서/표시 불일치.
- **AUD-07 (잠재 저장 경계값 오류·보통):** `addSkillXp`는 정상 게임 진행에서 스킬 최고 **20레벨**을 강제하지만, `normalizeGearSkills`의 구 저장 `skillLevels` 복원은 **100레벨까지 허용**. 외부/구버전 세이브의 21~100레벨이 그대로 남아 `skillScale` 등에 영향을 줄 가능성. **아직 실제 재현 테스트 전**이며 3단계에서 검증 필요.
- **AUD-08 (표시 설명 오류·작음):** '계승 확장' 특성 설명에 '스킬 구현 전 효과 대기' 문구가 남아 있지만 실제 계승 로직 `inheritanceSlots`/환생 계승은 구현되어 있음. 현재 설명은 혼란을 줄 수 있음. 8단계 확인.
- **AUD-09 (장기 밸런스 설계 미검증·보통):** `corePower`와 `coreEconomy`에는 명시적 구매 상한이 없고 1.85배 비용 성장. 상호 배타성은 없지만 '결국 모든 유효 강화 구매 가능'이라는 의도가 어느 시점까지 실질적으로 성립하는지는 장기 시뮬레이션 전 판단 불가. **문제 확정 아님**.
- **AUD-10 (추후 콘텐츠·작음):** 시간제 퀘스트 자동 회수는 **미구현**이나 공통 호출 로직은 이미 분리됨. 사용자 확정으로 자동 회수는 *향후* 구현 대상이므로 현재 버그 아님.

- `skillSlotCount`의 시점 자체는 최신 확정대로이므로 **레벨 해금 변경을 임의로 제안/수정하지 않음**. 영웅 경험치·콘텐츠·첫 환생 간 상호작용을 7/9단계에서 평가.
- 현재 스킬 등록은 **3종**인데 영구 장착 슬롯 최대 5개이므로 2칸은 채울 수 없음(AUD-06과 동일 원인). `renderGearSkills()` 보유 표시가 `/4`로 하드코딩되어 코드 실제 수량과 다름(AUD-06).
- 이미 스킬을 보유했는데 영웅 레벨업으로 빈 슬롯이 새로 열려도 `gainHeroXp()`는 기존 보유 스킬을 자동 장착하지 않음. 사용자가 직접 장착할 수는 있어 **의도된 선택 설계인지 UI 안내 확인**이 필요.

### 무기 시스템 상세: 이론적 드롭 분포

- STAGE 15 이후 **각 적 처치마다 드롭 시도 4.5%**(탐색 특성 최대 5랭크면 `0.045*(1+0.06*5)=5.85%`). 드롭된 무기 등급 분포는 일반 72%, 희귀 22%, 영웅 6%.
- 드롭된 무기의 성능 점수는 `tierMultiplier*(1+0.003*min(100,dropStage))`, 다른 옵션·장비 슬롯 없음. 현재 장착 중인 것보다 성능 점수가 높을 때만 **자동 교체**, 보관·합성·선택 장비 로직 없음.
- STAGE 100 획득 기준 점수 일반 ×1.456 / 희귀 ×1.664 / 영웅 ×2.015. 처음 STAGE 15 일반은 ×1.1704.
- STAGE 15~100을 1번씩 처치하고 기본 확률을 유지한다는 조건에서 무기 한 번 이상 드롭될 확률 `1-(1-0.045)^86` ≈ **98.09%**. **영웅 등급 드롭을 한 번이라도 경험할 확률** `1-(1-0.045*0.06)^86` ≈ **20.7%**. 탐색 특성 5랭크면 같은 구간 약 **26.1%**(독립 시도 가정). 실제 획득 무기의 최종 점수는 등급·시점·기존 무기와의 비교에 따라 다름.

### 스킬 강화·특성 수식 확인

- 스킬 레벨 필요 XP = `ceil(8*level^1.25)`; **LV1→5 누적 106XP, LV1→10 누적 567XP, LV1→20 누적 2,850XP**. 장착 스킬은 처치당 +1XP, 전 스킬 획득 후 중복 드롭 때 장착 중 스킬 하나 +3XP. 환생 시 계승 스킬도 레벨 1로 초기화하므로 장기적으로 20레벨까지 성장하려면 한 회차의 긴 플레이가 필요. **설계된 상한이 실제 활용되는지 미확정**, 7/9단계 확인.
- `training` 특성은 처치 XP +5%/랭크라고 표시하나 최종 지급 XP에서 **Math.floor** 적용. STAGE 1~5에서는 **0~5랭크 모두 처치당 2XP**로 실제 차이가 없음. STAGE 10에서는 0랭크 2XP, 5랭크 3XP. 초반 투자 체감이 매우 약할 수 있음.
- 특성 최대 투자량 10종 합계 **42포인트**. 영웅 LV60이면 최소 59포인트 획득(1레벨당 +1)해 모두 투자할 경우 **17포인트 남음**. LV60 이후 추가 레벨은 계속 포인트를 만들지만 현재 추가 특성 소비처가 없음. 무한 확장 게임이므로 콘텐츠 연동 장기 과제이지 즉시 오류는 아님.
- `normalizeGearSkills()`는 저장 스킬 레벨을 100까지 수용하지만 정상 `addSkillXp()`는 20에서 멈춤. **AUD-07과 같은 문제**, 새 발견 건으로 이중 집계하지 않음.

| 시스템 조건 | 첫 환생 평균 | 풀 시스템 대비 지연 |
|---|---:|---:|
| 장비+스킬+특성 전부 | **2361초** | 기준 |
| 장비 없이 | 2986초 | +625초 |

- 기존 CI에서 RNG 시드 3개와 동일한 스크립트 공격 우선/특성 우선 소비 정책 적용. 장비·특성 효과는 크게 나타나지만 **각 요소별 제거 실험이며 독립적 인과/최적 설계 점수는 아님**. 개별 스킬/장비 등급별 통제 실험 없음. 4단계 AUD-16과 동일한 근거로 교차참조.
- 두 스킬 선택 정책이 첫 환생 시간 **동일 2357초**였음. `attackWithSkillChoice`는 10초마다 `['overload','chain','bountySkill']` 순서로 직접 재배치하지만, 기본 자동 장착 및 슬롯 개방 타이밍과 얼마나 달랐는지 독립 계측이 없음. **0초 차이를 근거로 스킬 선택 무의미 단정 금지**(AUD-20).

### 오프라인 스킬 쿨타임의 구조적 오차

- 현재 `settleElapsed()`는 `dt=0.85초`씩 `step(dt,false)`를 호출. `skillTick()`는 축적 쿨타임이 임계점을 넘으면 **잔여 시간을 보존하지 않고 0으로 리셋**함.
- 기본 `chain`의 6초 쿨타임은 정산 중 `ceil(6/0.85)*0.85 = 6.8초`로 동작하여 **이론상 약 13.33% 느려짐**. `overload` 9초→9.35초(+3.89%), `bountySkill` 20초→20.4초(+2%). 보통의 포그라운드 작은 프레임에서는 상대적으로 오차가 작음. 특성 가속 레벨·여타 상태에 따라 편차 변화.
- 이 비교는 **스킬별 쿨타임 재발동 주기의 순수 수식 비교**임. 적 사망/오버킬/전투 전체 진행률·경제 손해를 실증한 값 아님. 오프라인 전투/성장 공정성 검증은 7·8단계로 연계.

### 5단계 발견 사항 (전체 종합 전 수정 금지)

- **AUD-21 (중요·콘텐츠 접근성):** 영웅 LV10에 열리는 2번째 스킬 슬롯을 첫 환생 전 전체 시간의 끝 2~7% 동안만 사용할 수 있음. 첫 30분의 스킬 전략 선택이 사실상 **1칸 선택**으로 압축됨. 슬롯 규칙 위반이 아닌 **영웅 XP 곡선·콘텐츠·환생 목표의 상호작용**. 7·9단계에서 재평가.
- **AUD-22 (보통·장비 콘텐츠 깊이):** 무기 1칸, 등급·습득 단계 기반 공격력 배율, 점수 상향 시 자동 교체만 구현. 유의미한 성능 기여는 확인됐으나 착용 선택·옵션·합성/성장 루프는 없어 **중간 연결 콘텐츠로서의 깊이가 제한됨**. 현재 크래시 버그 아님.
- **AUD-23 (보통·스킬 성장 길이):** LV20까지 한 회차 2,850XP가 필요하나 환생 때 LV1 리셋. LV20 전투 활용도/획득 속도는 장기 실측 전 판단 보류. 기존 슬롯 부족 AUD-06·기여율 AUD-16과 **동일 주제 연계**, 다른 증상만 독립 기록.
- **AUD-24 (보통·드롭 편차):** 스킬은 STAGE 20 이후 처치당 7.5% 무작위 드롭. STAGE20~40의 21번 처치에서 첫 스킬을 아직 못 얻을 이론 확률 `0.925^21` ≈ **19.5%**. STAGE20~55에서 약 **6.0%**. 획득 보장/천장은 없어 초기 운 편차가 발생할 수 있음. 캐주얼 장르의 기대·개인별 재미 평가 필요.
- **AUD-25 (낮음~보통·특성 반올림):** `training` 특성은 STAGE 1~5에서 5랭크를 찍어도 처치 XP가 2로 동일한 **무효 투자 구간**이 있음. 장기 효율과 별개로 효과 설명/초기 체감 검토.
- **AUD-26 (보통·오프라인 균형):** `skillTick` 쿨타임 누적 초과분 폐기로 오프라인 `dt=0.85`에서 일부 스킬 재발동 주기가 길어질 수 있음. 특히 LV1 `chain` 6→6.8초. 런타임/모바일 검증 전 확정된 실제 진행 피해량은 아님.
- **AUD-27 (장기 콘텐츠 공백):** 특성 총 42랭크가 상한인 반면 LV60 시 최소 59포인트 획득. **현재 전체 투자 완료 이후 포인트 사용처가 없음**. 사용자 장기 확장 정책에 따라 9/10단계에서 보완 필요 여부 검토.
- **AUD-28 (낮음·장착 편의):** 영웅 레벨업으로 장착 슬롯이 추가로 열려도 이미 보유한 스킬을 자동 장착하지 않음. 스킬 관리 화면에서 수동 장착 가능. 사용자가 원하는 방치형 편의성과 전략 선택 중 어디에 무게를 둘지 8·9단계에 실제 인터페이스로 확인.

### 5단계 결론

- 영웅 영구 성장, 슬롯·계승, 환생 초기화, 특성 투자/초기화, 3종 스킬의 피해/경제 효과, 1칸 자동 장비 교체는 **구현되어 있음**.
- 그러나 **초회차 대부분에 스킬 슬롯 1개**, 성장 가능한 스킬 종류 3개, 후반 슬롯 5개, 무기 선택 없는 단일 배율 루프가 합쳐져 **스킬 중심 콘텐츠라는 목표와 체감 간 간극**이 있음.
- 6단계는 **크레딧·퀘스트·코어·자동화·환생·위상 전환의 통합 자원 흐름**. 전체 점검 종료 전 실제 코드/테스트/수치 조정 보류.

### 영구 코어 투자 실제 비용

| 연구/강화 | 1→5 각 단계 구매 비용(코어) | 5레벨까지 총 |
|---|---|---:|
| 코어 출력 | 1, 2, 4, 7, 12 | **26** |
| 코어 경제 | 2, 4, 7, 13, 24 | **50** |
| 자동화 연구 | 3, 6, 11, 19, 36 | **75** |

- 자동화 연구 **3레벨까지 20코어**, 5레벨까지 총 75코어. 첫 환생 STAGE100 보상은 기본 **5코어**지만 더 깊이 돌파하면 코어 보상이 커질 수 있으므로 '반드시 15회 환생' 등으로 단정하지 않음.
- 자동화의 장점은 조작 편의이지 즉시 DPS/크레딧 영구 배율이 아님. 다른 두 투자에 비해 초기 환생이 느린 것 자체는 설계상 정상이므로 동일 시간 강제 비교 금지.

### 명확한 자동 환생 조건 불일치

- 표시 문구: `획득 코어가 누적 코어의 15% 이상이거나 3개 이상일 때 자동 재구성` — 자연어는 **OR**.
- 실제 판정: `gainCore() >= Math.max(3, Math.ceil(s.totalCores*.15))` — **AND**(두 하한을 모두 충족).
- 위상 압축 엔진이 0이고 코어 획득식이 현재 그대로인 조건에서:

| 누적 획득 코어 | 코드가 요구하는 한 번의 환생 보상 | 필요한 최소 스테이지 |
|---:|---:|---:|
| 0 | 3 이상 | 100 |
| 50 | 8 이상 | 122 |
| 100 | 15 이상 | 139 |
| 200 | 30 이상 | 171 |
| 500 | 75 이상 | 254 |
| 1,000 | 150 이상 | 371 |

- 누적 코어는 사용해도 `totalCores`에서 감소하지 않고, 위상 전환 때 0으로 리셋됨. 따라서 자동 환생을 켠 플레이는 계속해서 더 깊은 단계까지 갈 것을 요구함. 수치상 중후반 장벽이 매우 가팔라질 수 있음. **의도된 동적 재구성 임계치인지 UI 단순 문구 오기인지 최종 확정 전 구현 변경 금지**.

### 시간제 퀘스트 경제적 비중과 방치 조작성

- 퀘스트 보상 공식: `floor(base * 1.11^(min(60,best)-1))`. **최고 도달 스테이지 60에서 보상 증가가 멈춤**. 회수 가능량은 6/30/120초 퀘스트를 즉시 수령한다고 가정할 때 STAGE60 이상 약 **424.87 크레딧/초**.
- 최고 진행 단계 60에서 5회 보관 한도는 긴급 배송 **2,360**, 부품 회수 **28,325**, 장거리 운송 **94,420**, 합계 **125,105**. 회수하지 않으면 그 이상 쌓이지 않음. 편의성과 리워드 설계상 가능한 의도이지만 **수동 수령이 필요**.
- 기존 CI `highestTier` 전략의 60분 시점 강화 레벨 (`forge=32,gen=51`)을 그대로 대입하면, 위상/코어강화 없는 기본 생산율은 초당 **약 253,109**. 같은 시점 퀘스트 잠재 생산율 424.87은 기본 생산의 **약 0.168%**. **해당 CI 스냅샷의 이론적 비교**일 뿐 최초 30분·저레벨 구간의 가치를 부정하지 않음. 참고로 `forge=10,gen=5`면 같은 단계 퀘스트 수입이 기본 생산보다 큼.
- `coreEconomy` 및 위상 배율은 퀘스트 보상에 직접 중첩되지 않음. 이는 기존 확정 기록의 '중복 소득 폭증 방지' 방향과 양립할 수 있으므로 **즉시 오류로 판단하지 않음**. 다만 60단계 이후 기여도 감소와 자동 회수 미구현의 결합이 반복 재미를 약화하는지 7/9단계 확인 필요.

### 6단계 발견 사항 (전체 점검 종료까지 수정 금지)

- **AUD-29 (중요·기능 설명 불일치 + 장기 운영 위험):** 자동 환생 UI '15% **또는** 3코어'와 실제 `max(3,15%)`의 **동시 조건**이 다름. 총 코어 누적 시 요구 스테이지가 급상승(500코어→최소 254단계)하므로 장기 자동화가 사실상 지연·정체될 위험. **설명 또는 로직 중 어떤 쪽을 수정할지는 7·10단계 후 결정**.
- **AUD-30 (보통·자동화 편의성 한계):** 자동 구매는 구현되어도 **시간제 퀘스트 자동 회수는 미구현**, 자동 환생은 오프라인에서 의도적으로 차단됨. 이는 확정된 *추후 자동 회수* 로드맵과 관련된 콘텐츠 공백이지 기존 확정 규칙 위반으로 단정하지 않음. 조작 감소 계측과 연동.
- **AUD-31 (보통·후반 퀘스트 보상 정체):** 시간제 퀘스트 수입은 최고 스테이지 60에서 성장 종료, 주조기·처치 보상·강화 비용은 계속 성장. 기존 CI의 60분 샘플에서 퀘스트 잠재 생산의 상대 비중이 기본 생산의 약 0.17%에 불과. 이전의 55~65 성장 정체 AUD-14와 연계해서 **구간별** 유효성 평가. 퀘스트를 무조건 상향하라는 결론 금지.
- **AUD-32 (설계 파급 검증):** 위상 전환이 `autoLevel=0`, `autoBuy=false`, `autoRebirth=false`로 초기화되므로 이전에 획득한 자동화 편의를 다시 구매해야 함. 확정된 코어 계층 리셋과 **정적 일치**, 실제 장기 플레이에서 지루한 자동화 재해금이 되는지는 7/9단계 검토.
- **AUD-33 (검증 공백·전략 비교):** 과거 5회 환생 자동화 투자 비교는 자동 구매를 끄고 수동 구매 간격을 동일하게 설정하여 **편의성·무조작 성능 검증 불가**. 이전 인계의 동일 경고를 재확인했으며 신규 밸런스 오류로 이중 집계하지 않음.
- **AUD-34 (장기 접근성 교차 참조):** `phase()` 조건이 STAGE180+환생2회인데, 4단계 AUD-17의 101 이후 적 체력 급등과 연동한 **위상 계층 실제 진입 시간**이 미측정. 7단계에서 객관적 진행 가능성 확인 전 문제 단정 금지.

### 6단계 결론

- 코어의 **비배타적 투자**, 자동 구매의 상위 해금 티어 우선, 자동화 5레벨 상한, 환생 횟수 자체 무상 보너스 제거, 위상 전환 리셋은 **실제 수동 브랜치 코드에 반영**되어 있음.
- 가장 명확한 결함은 자동 환생 화면 설명과 로직의 충돌(AUD-29). 가장 큰 미검증은 장기 자동 환생의 실제 지속 가능성과 **자동화 투자에 대한 조작 편의성**.
- 다음 7단계에서 **장시간 시뮬레이션·전략별 동일 조건 비교(수동 입력 수, 자동 구매 ON/OFF, 연속 자동 환생 가능성, 초회차 60분)**를 점검하되 수정은 끝까지 보류.

- 60fps 공격 우선 10초 정책의 **30분** 도달 단계: 시드별 **63/63/65**, 60분에는 **112/111/113**. 기존 55~65 정체(AUD-14)는 **짧은 전체 플레이 구간도 상당 부분 점유**. 12개 60fps 공격 정책/시드 중 30분 이전 첫 환생은 **0건**, 최초 60분 내 환생은 **10건**.
- 정책에 따라 10초보다 30초 구매가 빠른 시드가 생기는 등 순서가 단조롭지 않음. 난수/드롭/구매 시점 상호작용으로 해석할 것.
- **첫 환생 ~60분 목표는 효율적 플레이 정책에서 아직 미달**. 그러나 사용자는 30분 1차 평가 중 환생이 필수 아니라고 확정했으므로 30분 미환생을 결함이라 부르지 않음.

- 기존 CI가 1초씩 `step(1,false)`한 것은 실제 전경 `loop()`의 최대 `dt=0.25`, 통상 수십 fps와 다름. 스킬 쿨타임, 여러 타격, 처치 후 새 적 처리 시점과 난수 경로가 바뀌어 **시드별 수분~10여 분 차이**가 생김. 일반적으로 작은 dt가 늘 빠르거나 느리다는 뜻은 아님.
- 기존 인계의 평균 2361초는 **그 1초 샘플의 측정값으로서는 유효**하나 실제 60fps 달성 시간의 확정값으로 사용 금지. **1/60초도 실기 FPS 변동을 완전히 대표하지 않음**.

### 코어 투자 순서와 편의성 — 연구 투자/구매 우선순위 통제한 신규 비교

- 동일한 시드, 최초 환생까지 같은 공격 우선+특성/10초 수동 구매·퀘스트 수령. 첫 환생 이후에는 **동일하게 자동화 연구 우선 투자**(자동화 1·2·3레벨 비용 3+6+11=20코어, 부족할 때 모으고 다른 코어 항목에 쓰지 않음). 수동 비교는 **상위 해금 티어 우선** 10초마다 구매, 자동 비교는 **실제 게임의 같은 티어 우선 자동 구매**. 퀘스트 수령은 양쪽 10초마다, 스킬/특성 투자는 같은 정책. 시뮬레이션 시차 `dt=0.25`, 일단 7회 환생 시 중단.
- 수동 연구형과 자동 구매형은 **같은 코어 강화 투자, 같은 해금 규칙**을 사용하여 이전 CI처럼 자동화를 꺼둔 상태만 비교하는 오류를 방지. 단, 자동 구매 주기(10→8→6초), 시점별 구매량과 RNG는 실제 구현에 의해 달라짐.

| 시드 | 연구 투자 동일·자동구매 OFF 7회 도달 | 연구 투자 동일·자동구매 ON 7회 도달 | 수동 구매 횟수 OFF → ON | 자동 구매 수 |
|---|---:|---:|---:|---:|
| 20261114 | 7966.25초 | 8126.75초 | 1737 → **265** | 1490 |
| 20261115 | 8025.50초 | 7692.75초 | 1737 → **265** | 1488 |
| 20261116 | 8485.00초 | 8295.50초 | 1718 → **265** | 1522 |

- **명확한 편의성 결과:** 수동 강화 구매를 시드별 약 **84.6~84.7% 감소**시킴. 자동 구매는 속도상 일방적인 이득/손해가 아님(3시드 중 2개는 빠르고 1개는 느림, 몇 % 수준). 자동화 연구의 본래 목적 '조작 부담 감소'는 이 정밀 비교에서 유효하게 작동.
- 자동 환생을 ON/OFF로 비교하면, 이 초기 7회 구간에서는 7회 달성 시간이 같았고 **자동 환생 ON은 5·6·7회차 3번을 대신 수행**했음(각 시드), OFF는 총 7번 사용자가 직접 환생. 연구 3레벨 해금은 4번째 수동 환생 뒤. **자동 환생은 누적 코어가 늘어난 장기 구간에서 다른 동작**을 하므로 이 결과를 장기 보장으로 과장 금지.
- 주의: 이 수동 비교는 **10초마다 최대 30개 강화 구매**를 허용하는 고입력 시나리오. 총 약 1,700회 단일 강화 클릭을 실제 사용자가 해야 한다면 현실성이 낮음. 자동화 ON은 수동 265회(대부분 첫 환생 전)만 필요. 장비/특성/수령/환생 조작까지 포함하면 진정한 완전 방치는 아님.
- 투자 순서가 다른 공통 정책 단일 시드(자동화 우선 vs 전투/경제 직접 강화): 7회 환생 **전투 수동 4896초 / 경제 수동 4765.25초 / 자동화 자동구매+퀘스트 60초 수령 8679.75초**. 여기서는 코어 배분과 수동 입력이 동시에 달라 **순수 성능 격차 지표로 사용 금지**. 자동화 투자 초기 지연 자체는 확정 설계상 허용.

### 자동화 투자 단일 경로의 장기 지속 가능성: 50,000초 전경 가속

- 별도 스크립트 정책: 첫 환생까지 수동 공격 우선/10초 구매·수령, 이후 **코어는 자동화 연구 5레벨 완성을 우선**으로만 보관·투자, 연구 LV1부터 자동 구매 ON, LV3부터 자동 환생 ON, 퀘스트는 이후 60초마다 수동 수령, 특성은 10초 간격 자동 투자 대행(실제 사용자는 직접 조작 필요), `dt=.25`, RNG 세 시드.
- 20261114/15/16 모두 게임 내 **50,000초(13시간53분20초)** 후 **환생 12회, 자동화 LV5, 코어 출력/경제 0, 총누적코어 75**, 현재 단계 129/129/130 부근. 12번째 환생은 각각 약 31,804 / 29,707 / 29,003초에 발생, 이후 남은 시간 동안 13번째 환생은 발생하지 않음.
- 해당 정책에서 코어 투자금이 5레벨까지 **75개 전부 자동화에 소비**되어 전투/경제 영구 강화가 부족함. 누적코어 75의 자동 환생 조건은 `ceil(75*.15)=12` 코어. 스테이지 129~130 부근에 장기간 정체. **문제 요인은 자동화 최우선이라는 극단적 투자 정책 + 누적코어 기반 상승 임계치 + 101 이후 체력 성장의 상호작용**. 다른 혼합 투자나 수동 환생/위상 전환까지 막힌다고 단정할 수 없음.
- 20261114의 퀘스트 수령 비교(모두 50,000초 전경 가속): 환생 12회는 동일했으나 첫 12회까지 걸린 시간은 퀘스트 10초 수령 ≈28,380초, 60초 수령 ≈31,804초, **첫 환생 이후 퀘스트 미수령** ≈34,304초. 수동 회수의 편의성/성장 속도 교환이 관측되지만 시드 난수 경로도 달라 엄밀한 단일 인과 추정은 아님.
- 위 측정은 수동 클릭이 아예 없는 자율 방치가 아님. 영웅 특성 투자를 스크립트가 대신했고, 전경 가상 시간으로 진행했으며, 사용자가 자동화 우선 외 다른 투자 전략을 고르면 결과가 바뀜. 따라서 12회 이후 영구적인 불가능 상태로 단정하지 않음.

### 자동 환생 ON 상태에서 위상 진입 방해 — 실제 코드 함수 실행

- 테스트 상태: `stage=179`, `best=179`, `rebirths=4`, `totalCores=20`, `autoLevel=3`; 적을 처치 직전으로 놓고 원본 `step(.25,true)` 실행.
- **자동 환생 ON → 단계 1, 환생 5회, 위상 획득 가능량 0**. 동일 상태에서 **자동 환생 OFF → 단계 180, 환생 4회, 위상 획득 가능량 1**.
- 자동 환생 동작은 스테이지 상승과 **같은 `step` 사이클에서 발동**, 사용자가 위상 버튼을 누를 기회보다 먼저 초기화 가능. 자동 환생의 코어 임계치가 낮은 동안 STAGE 180보다 훨씬 일찍 자동 재구성함.
- 현재 사용자는 자동 환생 토글을 OFF로 바꾸면 도달할 수 있으므로 완전 진행 불능 버그라기보다 **상위 계층 진입을 위한 자동화 설정 충돌**. 필요 시 알림·목표 예외·자동화 조건 설계 변경이 후보이나 **이번 단계는 제안/기록만**. 6단계 AUD-29(문구 OR vs 판정 AND)와 밀접하나 별도 사용자 영향.

### 7단계 발견 사항 (전체 종합 전 수정 금지)

- **AUD-35 (중요·측정 신뢰도):** `step(1)` 기반 과거 경제 시뮬레이션과 60fps `step(1/60)` 기준의 첫 환생 시간 차이가 크고, 차이 방향도 전략/시드에 따라 다름. 기존 39분21초 평균을 전경 실플레이로 일반화 금지. 실제 게임 프레임/드롭과 확률을 고려한 재검증 체계 필요.
- **AUD-36 (중요·60분 목표):** 신규 60fps 스크립트의 공격+특성/10초 정책 첫 환생 3시드 평균 **44분58초**, 상위 티어/10초 평균 **49분52초**, 초회 효율 60분 목표보다 빠름. 30분엔 12개 시험 모두 환생 전이라 1차 체험 조건은 충족. **최적 전략으로 증명하지 않았으며 숫자 튜닝은 아직 금지**.
- **AUD-37 (검증된 편의성 장점/관련 기록):** 동일 연구 투자/동일 구매 우선순위 통제 시 자동 구매는 7회 환생 직접 강화 클릭 약 **85% 감소**. 자동화형의 속도 지연을 무조건 심각한 밸런스 오류로 판단하지 않음. 반면 퀘스트 수령·특성 투자 등 수동 작업은 여전히 존재(AUD-30).
- **AUD-38 (중요 가능성·장기 자동화 정체):** 자동화 연구 LV5에 코어 전액을 먼저 투입하고 자동환생을 쓰는 정책이 50,000초 동안 12회 환생 뒤 스테이지 129~130 부근에서 재정체. 원인은 누적코어 대비 상승하는 자동 재구성 임계치와 영구 전투/경제 무투자의 합성. **극단적 순서 선택의 불리함인지 불건전한 장기 장벽인지는 혼합 정책 비교 필요**, AUD-29/17 교차참조.
- **AUD-39 (중요·상위 콘텐츠 접근성):** AUTO 환생 ON 상태는 STAGE 180 위상 진입 전에 자동 재구성을 일으킬 수 있음. 동일 합성 저장 상태에서 ON/OFF 실행 차이로 재현. 사용자가 직접 OFF할 수 있지만 자동화 목적과 반대되는 강제 개입을 요구하므로 9/10단계 UX·설계 검토.
- **AUD-40 (현실성/조작 비용):** 10초 간격 최대 30건의 수동 강화 구매 대행 스크립트는 7회까지 약 **1,700~1,900번의 강화 클릭**을 가정. 실제 모바일 저입력 플레이와 다를 수 있음. 자동화 평가 시 조작 횟수·퀘스트 수령·특성 투자·환생 터치를 모두 합산하고, 고입력 최적 정책을 일반 유저 평균처럼 서술 금지.

### 7단계 결론

- **원본 코드 기반 신규 테스트 실행 및 다회차 비교 완료.** 실제 브라우저/휴대전화 통합 테스트는 아직 아님.

### 신규 원본 JS 60fps / 60초 fake-DOM 갱신 계측

| 측정 항목 | 3,600프레임 호출에서 측정된 횟수 | 프레임당 대략 |

- 게임은 `loop()`에서 `step(dt)`와 `render()`를 **전경 매 프레임 실행**. 실제 보이는 전투 탭에 상관없이 성장·특성·퀘스트·재구성·위상 등 모든 데이터를 갱신.
- `#cacheTimer.innerHTML=QUESTS.map(...)`은 **세 퀘스트 행의 DOM을 매 프레임 통째로 교체**하는 구조. 보상이 초 단위로 표시되는데도 수십 fps에 갱신됨. 주요 수정 후보는 논리 값 갱신 주기 분리, 값 변경 시 DOM 갱신, 퀘스트 목록 노드 재활용 등이나 **수정은 종합 후**.
- 초기 버튼을 재활용하는 `updateButtons`와 `renderTraits` 설계는 매 프레임 새 버튼을 만들지 않아 긍정적. 다만 보이지 않는 성장/재구성 메뉴 텍스트·상태를 매 프레임 수십 번 다시 대입하는 구조는 남아 있음.
- 동일 fake-DOM 3,600프레임을 30fps/120초 간격으로 실행해도 `textContent=169,259`, `disabled=75,621`로 **프레임 횟수에 비례**(게임 시간·표시 내용과 무관). 실제 레이아웃/리페인트/발열이 발생하는지 모바일 실기 검증 전 단정 금지.
- index.html 별도 500ms `setInterval`은 통계 3종을 갱신함. 화면이 숨겨진 동안 타이머 정책은 브라우저별로 다를 수 있음.

- 실제 게임은 이미지 **아래쪽의 별도 HTML `#hpBar`**를 `100*enemyHp/enemyMax` 비율로 실시간 갱신함. 보스 체력이 100%인 순간에도 그림 안 78.3% 또는 73.0%가 표시될 수 있어 **상반된 체력 표시 2개**가 공존. 모바일에서 작아서 식별 불가능할지는 실기 미확인이나 **정적 이미지 내용과 UI의 구조적 충돌은 확정**.
- 두 보스는 세로형 화면에서 가로형 이미지. CSS `width:49%; max-width:49%; height:clamp(220px,36svh,350px); object-fit:contain; object-position:center bottom`을 적용. 390px 화면에서 일반적인 패널 폭/좌우 여백으로 추정하면 **주인공 실제 표시 높이 약 268px vs 보스 약 107~115px**로 큰 차이 가능. 이는 **CSS·이미지 종횡비 근사**이지 브라우저 실측 크기가 아님. 보스가 상대적으로 작아지면 강한 적의 존재감이 약해질 위험.

### 스테이지별 실제 이미지 다양성

`spawn()`의 우선순위 분기: `%20===0`은 과열 보스, `%10===0`은 수호 보스, `%5===0`은 장갑 적, `%3===0`은 기동 적, 그 외 정찰 적.

| STAGE 1~100 분포 | 출현 스테이지 수 |
|---|---:|
| 정찰 적 (기본 SVG) | **53** |
| 기동 적 (SVG) | **27** |
| 장갑 적 (SVG) | **10** |
| 수호 보스 (WEBP) | **5** |
| 과열 보스 (WEBP) | **5** |
| 합계 | **100** |

- STAGE 1과 2 모두 정찰 적, 7과 8도 정찰 적이며 비보스 적은 3종 패턴을 순환. 게임 내 레벨·보스 난이도 상승에 따른 **추가 외형 변화/지역 전환/이펙트 해금 없음**.
- 게임 전체 기간의 시각적 반복성으로 이어질 가능성이 있으나 적은 단순 연출 허용이라는 사용자 방향에 따라 **당장 모든 적을 고품질로 새로 제작해야 한다는 결론 금지**. 특히 주인공·스킬 액션 연출 우선으로 연결.

### 실제 애니메이션·피드백과 체감 한계

- 존재: `hero-breathe` 2.8초 세로 이동, `enemy-hover` 2.2초 부유, 보스 `boss-presence` 1.8/1.6초 확대·부유, 일반 타격 시 `combatImpact()`의 적 이미지 밝기/그림자 170ms 효과(최소 간격 180ms), 적 체력바 CSS 전환 0.12초. reduced-motion 조건 반영.

### 반복 플레이의 동기/관측 가능한 한계

- 장점: 첫 환생 뒤 영웅 레벨·특성 영구 유지, 코어의 비배타적 전투/경제/자동화 투자, 자동 구매로 직접 강화 클릭 약 85% 감소(7단계 통제 시뮬레이션), 위상 전환의 새로운 성장 계층 존재. '이전 장벽을 더 빠르게 돌파' 동기의 기능적 기초는 구현됨.
- 위험: 단기적으로 환생 루프는 **같은 5개 적 외형, 동일 3종 스킬 중 1개 장착 중심, 동일 7종 숫자 강화의 반복**. 새 회차마다 화면의 전투 연출·해금 방식의 다양성이 자동으로 늘지 않음. 사용자는 쉽게 지루함을 느낄 수 있고, 콘텐츠 변화를 계속 확장할 예정이므로 **반복을 덜 지루하게 하는 작은 콘텐츠/시각 피드백의 우선도**가 높을 수 있음.
- `logText`는 단일 마지막 문구만 보관. `grantDrop`의 획득 문구는 같은 처치의 `gainHeroXp` 레벨업 또는 추후 `unlock`·`rebirth` 이벤트로 덮어씌워질 수 있고, 이벤트 이력 탭이 없음. 중요한 드롭·레벨업 보상이 눈에 잘 띄지 않을 위험. **소스상 표현 방식 확인**, 실제 놓친 빈도는 실기 미검증.
- 퀘스트는 3개의 **독립 시간제 보상**이고 전투와 별개로 정상 적립되며 6단계에서 후반 경제 비중 감소를 확인. **이벤트/선택이 발생하는 별도 미니게임·이야기 퀘스트는 아님**. 단계적 목표의 가치에 대한 사용자의 실제 판단 필요.

### 9단계 발견 사항 (10단계에서 원인 통합/수정 우선순위 결정)

- **AUD-47 (큼·시각적 정보 충돌):** 실제 보스 WEBP 2종 안에 고정 체력바+퍼센트(78.3%/73.0%)가 포함되어, 현재 게임의 `#hpBar` 실시간 체력바와 의미 충돌. **실제 이미지 자산 직접 확인**, 시각 자산 수정/표시 구조 검토 필요. 4단계 AUD-15(보스 정체성)와 구별.
- **AUD-48 (보통~큼·전투 가시성):** 주인공 세로 410×640 vs 보스 가로 461×286/307이라는 자산 비율 차이. 현재 49% 폭/contain 배치에서는 보스가 주인공보다 실제로 작게 렌더링될 위험. 근사치상 390px 폭에서 주인공 약 268px 높이, 보스 약 107~115px 높이. **실제 CSS 렌더 캡처 전 추정**. 8단계 AUD-42의 관전 화면 배치와 연계.
- **AUD-49 (큼·핵심 연출 미구현):** 애니메이션이 정지 이미지 부유/확대와 일반 타격 피드백에 집중. **주인공 공격·고유 스킬·획득/장비 변화를 보여주는 전용 연출 미구현**. 스킬 중심 콘텐츠 약화 AUD-06/16/21과 묶어서 판단. 사용자의 그래픽 우선순위를 고려해 장기 후순위로만 미루지 말 것.
- **AUD-50 (보통·시각 일관성/반복):** 주인공 일상 애니메이션 일러스트, 3종 아이콘형 일반 적, 2종 고밀도 로봇 보스의 표현·비율 차이. 1~100 단계에서 정찰 적 53회, 기동 적 27회, 장갑 적 10회, 보스 각 5회 출현하며 환경 변화 없음. 단순 적 표현 허용 설계 고려, **현재 실제 플레이 만족도 검증 전 전면 교체 단정 금지**.
- **AUD-51 (보통~큼·콘텐츠 공백):** STAGE 20 스킬 드롭 시작이 `milestoneTargets`에 명시되지 않으며 초기 보상을 즉각 확신할 수 없음. STAGE 25~45와 65~100의 많은 단계가 추가 기계적 선택/시각적 보상 없이 반복. 기존 AUD-14(55~65 정체)/AUD-21(스킬 슬롯 늦게 열림) 연계. **장르 특성상 대기 자체는 오류 아님**.
- **AUD-52 (보통·보상 피드백):** `logText` 한 줄이 다수 이벤트에서 덮어써질 수 있고, 전투 화면에 장비/스킬 획득 별도 연출/이력 없음. 새 드롭과 영웅 레벨업의 보상 인지가 약해질 위험. 추가 시각·정보 피드백 여부는 10단계에 판단.
- **AUD-53 (콘텐츠/접근성 검증 공백):** 사이트 배포본에 오디오/전용 스킬 이미지가 없고, 실제 전투 애니메이션 체감·기기 오디오 정책·반복 관전 재미는 미검증. 오디오 자체는 사용자 확정 필수라고 단정 금지. 10단계에서는 확정 미구현과 체감 미확정을 구분.

### 9단계 결론
