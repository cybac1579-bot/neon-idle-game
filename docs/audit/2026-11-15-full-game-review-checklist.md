### 2단계 상세 문제/개선 후보

- **AUD-06 (콘텐츠 공백·보통~큼):** 실제 `SKILLS`는 **3종**(`overload`, `chain`, `bountySkill`)인데 스킬 슬롯은 최대 5개이고 UI에는 '보유 x/4'로 표시. **5칸 모두 활용하는 선택지 자체가 현재 없음**. 크래시 버그가 아니라 스킬 중심 성장 콘텐츠 부족이며 5·9단계에서 실제 체감 영향 판정. 주석에도 '스킬 4종'으로 적혀 있어 문서/표시 불일치.
- **AUD-07 (잠재 저장 경계값 오류·보통):** `addSkillXp`는 정상 게임 진행에서 스킬 최고 **20레벨**을 강제하지만, `normalizeGearSkills`의 구 저장 `skillLevels` 복원은 **100레벨까지 허용**. 외부/구버전 세이브의 21~100레벨이 그대로 남아 `skillScale` 등에 영향을 줄 가능성. **아직 실제 재현 테스트 전**이며 3단계에서 검증 필요.
- **AUD-08 (표시 설명 오류·작음):** '계승 확장' 특성 설명에 '스킬 구현 전 효과 대기' 문구가 남아 있지만 실제 계승 로직 `inheritanceSlots`/환생 계승은 구현되어 있음. 현재 설명은 혼란을 줄 수 있음. 8단계 확인.
- **AUD-09 (장기 밸런스 설계 미검증·보통):** `corePower`와 `coreEconomy`에는 명시적 구매 상한이 없고 1.85배 비용 성장. 상호 배타성은 없지만 '결국 모든 유효 강화 구매 가능'이라는 의도가 어느 시점까지 실질적으로 성립하는지는 장기 시뮬레이션 전 판단 불가. **문제 확정 아님**.
- **AUD-10 (추후 콘텐츠·작음):** 시간제 퀘스트 자동 회수는 **미구현**이나 공통 호출 로직은 이미 분리됨. 사용자 확정으로 자동 회수는 *향후* 구현 대상이므로 현재 버그 아님.

- **AUD-11 (높은 우선 후보, 구버전 잔액 손실):** `main`의 기존 정기 회수는 STAGE 60에서 `cachePayout()` 최대 183,421/회, 5회 보관 최대 **917,105** 크레딧. 새 버전 `load()`는 이 `cacheCredits`를 `questCredits[1]`에 넣지만, 새 '부품 회수' 퀘스트의 STAGE 60 한도는 `floor(12 * 1.11^59) * 5 = 28,325`. 다음 보상 주기가 발생하면 `questTick()`이 `min(새한도, 기존보관+추가보상)`을 적용해, **917,105 → 28,325** (**888,780 감소, 약 96.91%**)할 수 있음. 이 구버전 최대 잔액은 옛 코드로 합법적으로 누적 가능한 상태임. 다른 단계 소스 수식 대조: STAGE 15 365→255(−30.14%), 25 2,080→730(−64.90%), 40 28,280→3,510(−87.59%), 55 384,310→16,810(−95.63%). 보상 주기 전에 즉시 수령하면 기존 잔액을 수령 가능하므로 **무조건 손실은 아님**. 저장 데이터 이전 시 무손실 보관·별도 잔액 보호를 고려하되 아직 수정하지 않음. 기존 'legacy credit cache migrates...' 테스트는 이전 직후 즉시 수령만 확인하므로 **다음 적립 시 손실을 검출하지 못함**. 실제 런타임 재현은 미실시.
- **AUD-07 상세 확인 (중간 우선 후보):** `normalizeGearSkills()`의 저장 스킬 레벨은 `Math.min(100,...)`이어서 구세이브의 21~100레벨 수용. 정상 `addSkillXp()`에서는 20레벨 상한. `skillScale`은 LV20 **×1.76**, LV100 **×4.96**이므로 정규화 불일치가 실제 스킬 효과 경로에 연결됨. 정상 획득 경로의 오류가 아닌 구세이브/변조 데이터 경계값 문제; 재실행 없이 정적 확인.
- **AUD-12 (검증 공백):** 저장 거부 시 실패 메시지를 표시하고 진행은 계속되지만, 브라우저 저장이 **일시적으로** 거부됐다가 복구되는 경우 기존 유효 저장 데이터가 덮어써지는지 테스트 없음. 현재 실증 오류로 확정하지 않음.
- **AUD-13 (검증 공백):** 두 시간 한도 정산은 기존 Node 테스트 통과지만 실제 Galaxy S25+ 브라우저에서 큰 저장 데이터·장시간 복구의 정산 지연/메모리/화면 중단은 검증되지 않음. 8단계 실기 확인과 연계.

### 수식으로 확인된 적 체력의 불연속 증가

- 기본 매 단계 `×1.26`, 20단계 단위 `×1.30`, STAGE 71~100 추가 단계 `×1.045`, STAGE 101 이상 추가 단계 `×1.4`.

### 스킬의 전투 기여 가능성 (5단계 교차 참조)

- 레벨 1의 `overload`는 공격력 3배를 9초마다, `chain`은 1.7배를 6초마다. **두 스킬을 동시 장착하고 오버킬/대기 지연이 없다는 이상화 가정**에서 추가 피해 기대량 = 기본 공격력의 약 **0.617배/초**.
- 일반 공격은 공격 간격 0.85초에서 약 1.176배/초, 상한 0.1초에서 10배/초. 스킬의 **상대적 추가 피해 기여도**는 조건 동일 시 약 **52.4% → 6.17%**로 감소. **스킬이 후반 중심 콘텐츠인지** 5·9단계에서 평가; 실제 DPS 계산·효과는 스킬 레벨/쿨타임/특성/적 HP의 영향을 받음.
- 기존 `BALANCE_SYSTEM_CONTRIBUTIONS`의 3시드 평균 첫 환생: 풀 시스템 2361초, 장비 미사용 2986초(**+625초**), 스킬 미사용 2546초(**+185초**), 특성 미사용 2963초(**+602초**). 무작위 드롭과 상호작용이 섞이므로 **스킬이 무의미하다는 증거는 아님**. 스킬 기여의 상대적 부족은 후속 분석 후보.
- 기존 `BALANCE_SYSTEM_COVERAGE`에서 두 스킬 선택 정책의 첫 환생 시간 차이가 **0초**로 보고됨. 정책이 실제로 구별되는 장착 선택을 했는지부터 검증 필요; 0초를 '스킬 선택이 무의미하다'고 해석하지 말 것.
