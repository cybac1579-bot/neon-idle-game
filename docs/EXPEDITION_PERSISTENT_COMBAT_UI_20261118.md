# 네온 방치단 — 전투 상시 관전형 UI 전면 개편 (2026-11-18)

## 변경 이유 — 사용자의 2차 귀환 실제 플레이 피드백
- 이전 prototype는 전투 탭과 성장 탭을 번갈아 선택해야 했다. 전투 관전과 성장 구매가 플레이어 입장에서는 서로 배타적으로 된 UI 설계 오류다.
- 사용자는 환생용병단처럼 **특정 팝업 상황을 제외하면 전투 장면이 화면에 항시 존재하는 형태**를 원했다. 게임 조작량이 충분히 큰 상태에서 전투를 가리는 구조는 관전형이 아니라 관리 메뉴형 게임처럼 느껴졌다.
- 1차 귀환 가능 상태를 UI상 발견하지 못한 경험이 있었으므로 귀환 기능은 단순히 설명 문구 추가가 아닌 항상 접근 가능한 **독립 메뉴**와 가능 시점의 **전투 바로가기**가 필요하다.
- 지루함에 대한 피드백: 유물을 얻어도 숫자만 바뀌며 플레이 방식은 동일. 이번 회차는 UI 문제를 고친 뒤 **실제 유물 작동 방식 변환**을 설계·검증하는 다음 단계를 열기 위한 기반이다. 이번 UI만으로 유물 다양성 문제까지 해결했다고 주장하지 않는다.

## 핵심 레이아웃
- 모바일 세로 360·390·412px을 검증 대상으로 하는 고정높이 100dvh command deck. 화면은 **상단 브랜드 / 3개의 기본 지표 / 상시 전투 / 전투와 분리된 4개의 메뉴 탭 / 메뉴 내용의 독립 스크롤**로 구성한다.
- `#battleScreen`은 더 이상 '선택 중인 탭'이 아니다. `#workbench`만 상하 스크롤한다. 메뉴를 넘기거나 성장 구매를 계속 눌러도 실제 적, 용병, 이동, 피격, HP 바, 보스 표시, 전투 메시지, 상자 목표는 남는다.
- 정보 과밀 방지: 전투 영역에는 현재 거리·크레딧·최고 거리, 전투 장면·HP, 최근 전투 메시지·다음 상자만 남긴다. 개별 용병 기여, 편성 통계, 세부 성장 숫자는 필요할 때 성장 탭에서 접기/펼치기로 본다.
- `#squadScreen`은 기본 선택; 소집·훈련 2개 즉시 성장 버튼과 다중 구매 설정을 상단에 둔다. 자동 구매는 사용자 의도대로 **기본 꺼짐** 유지하며, 자세한 정책 설명은 접는다. 병종별 정보와 전선 세부 통계도 접어서 조작 구역 공간을 줄인다.
- `#supplyScreen`: 의뢰 구매/자동 수익 확인. `#archiveScreen`: 영구 유물 수집/상자/기록/JSON/전체 저장 백업. `#returnScreen`: 현재 환생 성과·영구 코어 투자·귀환 버튼·최근 귀환 비교.
- `#returnQuick`: 귀환 코어 획득이 가능한 상태일 때에만 항상 보이는 전투 장면 상단 클릭 안내. `#returnTab`도 `+코어` 표시로 알려준다. 바로귀환은 안 하고 **귀환 상세 메뉴**를 연 뒤 기존 확인 절차로 귀환.
- 전투는 매 350ms 갱신하고 작업 패널은 약 1.2초 주기로 갱신, 버튼 행동과 탭 이동 때 즉시 렌더. 전투가 메뉴 전환 때 DOM에서 분리/재생성되지 않아 용병 이동 효과가 중단되지 않는다.
- 전체 디자인은 어두운 지휘소/전술 무대와 옅은 황동·녹청색 포인트로 정리. 그림/일러스트는 기존 CSS 기호 임시 placeholder지만 시안이 아니라 **실제 실행 UI**이며, 게임 규칙에 없는 구매/조작 버튼을 새로 도입하지 않는다.

## 기술/데이터 보존
- 변경 범위: `site/expedition.html`, `site/expedition-app.js`, `scripts/build-expedition-standalone.cjs`, `tests/expedition-browser.test.cjs`.
- 엔진 `site/expedition-engine.js`는 UI 개편 목적으로 수정하지 않는다. 기존 유물 종류/보상/코어·투자·자동 구매·환생 계산은 유지한다.
- 프로토타입 저장 키 `neon_expedition_prototype_v1`, 레거시 저장 키 `neon_rework_07`은 각각 그대로. 공개 `main`/Pages와 다른 독립 원형으로 테스트한다.
- 현재 사용자가 보관 중인 구 `file://` HTML은 다운로드만으로 자동 업데이트되지 않는다. 기존 파일에서 **도감 → 전체 저장 백업** JSON을 먼저 내려받고, 새 파일에서 **유물 → 저장 파일 복원**으로 옮긴다. '내 플레이 기록 JSON 내보내기'는 **분석용이며 저장 복원용이 아님**.
- 실기기에서 저장 데이터 복원 후 2회 이상 귀환한 진행을 이어가더라도 엔진 데이터 구조는 동일. 구 버전 UI에서 프로토타입 저장이 자동 공유된다고 가정하지 말 것.

## 테스트 필수 통과 기준
1. 360/390/412 모바일 Chromium에서 전투 영역이 실제로 viewport 내부에 존재하고, command tabs/하단 스크롤이 겹치지 않는지 bounds로 확인.
2. 성장 탭에서 스크롤 최하단, 보급 탭, 유물 탭, 귀환 탭 중 어느 화면에서도 전투가 화면에 남는지 검사.
3. 10거리 보스 격파 등 귀환 가능 조건에서 상시 귀환 안내/탭 배지가 나타나고, 누른 뒤 상세 성과를 검토하고 귀환할 수 있는지 검사.
4. 상자 획득·일괄 개봉, 영구 기록, 귀환 결과 팝업, 저장/복원, JSON 추출, 이전 게임 저장 미변경.
5. CI가 `scripts/build-expedition-standalone.cjs`로 생성한 HTML 자체를 네트워크 차단된 `file://` Chromium에서 3개 viewport로 확인. 실제 Galaxy S25+ 관전과 조작·배터리/발열은 별도 수동 테스트가 필요.

## 아직 미해결
- 유물이 숫자 강화 이상으로 전투·경제·탐사 방식을 바꾸도록 역할을 확대하는 별도 콘텐츠 설계.
- 기존 한 장면에 동시 표시 가능한 캐릭터는 8명 내외의 유닛 심볼 placeholder라서 용병 규모가 커지면 뒷줄 요약 표시가 남는다. 실제 일러스트/이펙트 품질은 이번 UI의 목표가 아니다.
- 다양한 모바일 브라우저/화면 높이/키보드와 전환 시 실제 사용자 체감은 실기기 피드백을 받아야 한다.
