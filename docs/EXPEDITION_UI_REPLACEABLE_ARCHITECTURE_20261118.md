# 네온 방치단 — 임시 UI 교체 가능 구조 (2026-11-18)

## 현재 화면은 미확정
이 문서는 2026-11-18 실제 사용자의 명시적인 결정에 따라 작성했다.

- **현재 상시 전투 + 하단 성장·보급·유물·귀환 인터페이스는 최종 확정 시안이 아니다.**
- 현 디자인, 색상, 버튼 모양, 전장 배경, 아이콘/문자 심볼, 패널 크기, 일러스트/애니메이션을 모두 다시 만들 수 있어야 한다.
- 이전 `site/expedition.html`/CSS 안에 실험적인 그래픽을 최종 방향으로 고착시키지 않는다.
- 사용자 경험에서 유지할 **기능적 원칙**은 "전투를 관전하는 동안 성장 메뉴를 이용할 수 있어야 한다"는 것이지, 반드시 현재 위/아래 레이아웃을 영구 보존한다는 뜻은 아니다.
- 실제 완료작/기성 게임 수준의 재미와 시각적 완성도를 확보하는 이후 개편 작업을 막지 않도록, 플레이 테스트 원형의 레이아웃은 과도하게 확장하지 않는다.

## 교체 가능한 계층과 책임

| 경로 | 현재 책임 | 향후 교체 범위 |
|---|---|---|
| `site/expedition-engine.js` | 전투/성장/수익/유물/귀환/저장 상태 정규화의 **순수 게임 엔진** | UI 교체 시 **원칙적으로 수정하지 않음** |
| `site/expedition-app.js` | 상태 생성·오프라인 복귀·자동 저장·입력 후 엔진 호출·JSON 백업/복원·350ms 진행 루프 | 게임 행동이 변경되는 경우만 수정. 화면 색상·배치는 책임 아님 |
| `site/expedition-ui.js` | `window.ExpeditionUI.create(ctx)` 인터페이스로 메뉴/전투/결과 정보의 DOM 렌더링을 담당하는 교체용 **뷰 어댑터** | 레이아웃/정보 구조 변경에 맞춰 전면 교체 가능. 저장/엔진 계산 금지 |
| `site/expedition-ui.css` | 현재 UI 디자인 및 세로 화면 레이아웃 전용 **교체형 스킨** | 색·폰트·구도·모션·반응형 레이아웃 전체 교체 가능 |
| `site/expedition.html` | 현재 버전의 DOM 구조, 화면 표시/버튼 연결을 제공하는 **교체형 셸** | 완전 교체 가능. 최소 UI 계약 유지 또는 어댑터와 함께 새 계약 정의 |
| `site/expedition-field.js` | 용병 개별 포지션/피격/회복 큐를 화면에 투영하는 **전투 시각화 어댑터** | 추후 스프라이트·Canvas 등으로 대체 가능. 엔진에 전투 중복 구현 금지 |
| `scripts/build-expedition-standalone.cjs` | CSS와 뷰 어댑터까지 모두 포함하는 오프라인 단일 HTML 테스트판 제작 | UI 구성 파일이 늘어나면 패키징 목록만 갱신 |

## UI와 게임 상태 사이의 계약
- 브라우저 진입점은 엔진 → 전투 시각화 → `ExpeditionUI` 뷰 → 컨트롤러 순서로 로드한다.
- 컨트롤러는 `ExpeditionUI.create({engine,state,byId,fmt,safe,row,ratio,getBuyCount,getNotice})`를 통해 렌더링을 요청한다.
- 교체 가능한 뷰는 최소 `{screen,renderBattle,renderPanel,render,updateBuyCount,returnReportHtml}` 메서드를 제공한다.
- **현 버전 HTML**은 `battleScreen`, `workbench`, `squadScreen`, `supplyScreen`, `archiveScreen`, `returnScreen` 등 기존 컨트롤러와 화면이 요구하는 DOM 포트를 유지한다. 새로운 HTML은 기존 DOM 계약을 지키거나 **새 뷰 어댑터와 연결을 한꺼번에 갱신**할 것.
- DOM 포트 및 스타일 분리 계약 자동 테스트: `node tests/expedition-ui-contract.test.cjs`.
- 브라우저 기능 회귀: `node tests/expedition-browser.test.cjs`, 오프라인 파일 버전: `node tests/expedition-offline-browser.test.cjs`. CI는 브라우저 360/390/412px에서 버튼, 정보 표시, 전투 관전, 저장·복원과 가로/세로 화면 겹침을 검증한다.
- 시각화 계층이 게임 상태를 바꾸거나 새로운 저장키를 도입해서는 안 된다. `neon_expedition_prototype_v1` 스키마/키는 유지하고, 레거시 `neon_rework_07`에 접근하지 않는다.

## 실제 UI 교체 시 작업 순서
1. 기존 `site/expedition-ui.css`와 `site/expedition.html`은 새 버전으로 **수정/교체하되**, 구 버전 소스의 영구 확정이 아니라는 점을 명시한다.
2. 필요하면 `site/expedition-ui.js`를 함께 교체한다. 게임 계산, 영구 투자 수치, 수집 도감 데이터 등은 엔진 함수를 사용한다. 별도 전투/경제 시뮬레이터를 UI에 넣지 않는다.
3. 전투 연출 교체 시 `site/expedition-field.js`를 바꿔도 되지만 엔진의 개별 용병 상태를 읽고 시각화하는 책임을 유지한다.
4. 위 스왑 후 DOM 계약/기존 기능/실제 브라우저 플레이/기존 저장 로딩/오프라인 단일 HTML CI를 모두 검사한다.
5. Galaxy S25+ 세로 실제 기기에서 **성장 버튼을 누르는 동안에도 전투를 볼 수 있는지**, 입력 편의성, 장기 전투 관전, 성능·발열을 사용자 테스트로 검증한다.
6. 새로운 UI는 사용자가 따로 확인·승인하기 전까지 **실험 시안으로만 취급**한다.

## 현재 기준에서 의도적으로 변경하지 않은 것
- 첫 2회 환생/유물 진행을 포함한 사용자 저장과 회복 동작
- 적 체력, 자동 구매, 보급 경제, 유물 수집/보관, 코어 재화, 플레이어 레벨·특성 등 성장 규칙
- 사용자가 원하지 않는 탭 액티브(연타), 자동 강제 귀환
- 기존 공개 게임 `main` 브랜치와 `site/index.html`

## 남은 확장 여지
- 컨트롤러의 버튼 이벤트는 아직 현 DOM ID에 직접 연결되어 있어, **ID와 입력 종류를 통째로 바꿀 경우에는 컨트롤러 연결부도 조정해야 한다.** 현재 구조가 모든 미래 UI를 자동 호환한다는 주장은 하지 않는다.
- 엔진↔뷰 경계는 분리되었지만 대규모 장비·유물 시스템 개편은 새로운 데이터 인터페이스가 필요할 수 있다.
- 현재 UI에서 중요했던 '항상 전투 관전' 원칙을 유지하면서도 화면 디자인·정보 배치 방식은 추후 다시 선택할 수 있다.

## 사용자에게 보고할 기준
완성/최종 인터페이스라는 표현은 쓰지 않는다. 기준 UI는 "교체 가능한 **임시 플레이 테스트 화면**"이며, 테스트 결과는 실제 검증한 범위만 보고한다.
