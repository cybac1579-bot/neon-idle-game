- 기준: `integration/reconcile-main-redesign-20261114`, 독립 `site/expedition-engine.js`.
- 실행 스크립트: `tests/expedition-route-audit.cjs` (기존 CI 실행 경로 `tests/expedition-autobuy-pacing.cjs`에 연결).
- 동일한 세 시드 `123456789`, `987654321`, `20261118` 사용. 같은 실험 조건에서 난수가 결정적이지만 구매 시점이 달라지면 이후 RNG 소비도 달라질 수 있다.
- 세 번 연속 귀환, 매번 **거리 35 도달**을 비교 목표로 선택; 미도달 시 해당 탐사는 **90분에서 중단**. 보급 상자는 300초마다 사용자가 직접 개봉한다고 가정. 귀환 후 획득 코어는 모두 가능한 만큼 전선(valor)에 투자.
- 균형 수동 구매는 동일한 훈련→소집→보급 우선순위를 **4초 또는 20초마다 한 번** 실행하며 성공 후에만 구매 순서를 진행한다. 자동 모드는 4초마다 구매를 판단한다.
- 여기서 **35거리는 테스트용 비교 기준이며 실제 첫 귀환 조건이 아니다. 실제 원형은 10거리부터 귀환할 수 있다.**

## 첫 귀환 기준에 대한 별도 발견
- 균형 자동의 첫 **10거리 귀환 조건** 달성: 40 / 44 / 52초.
- 4초 균형 수동: 40 / 44 / 52초.
- 20초 균형 수동: 84 / 76 / 76초.
- 용병만: 36초, 훈련만: 72초, 보급만: 112초 (각 시드 동일).
- 이전에 설정한 '최적 플레이의 첫 환생 약 60분'과 크게 다르다. 다만 지금은 `환생용병단`의 반복 원정·유물 수집 구조를 우선 검증하는 **독립 신규 원형**이므로, 단순 시간 게이트나 숫자만 늘리는 조정으로 곧바로 맞추지 말 것. 먼저 첫 귀환의 의미, 반복 동기, 10/20/35거리 전투와 보상을 정리해야 한다.

## 코드/운영 결정
1. 현재 단일 구매 모드는 사실상 전용 정책이다. UI의 '우선'이라는 잘못된 표현을 '훈련만/용병만/보급만'으로 정정. 균형만 세 항목을 순환한다.
2. 자동 구매가 상자·귀환·코어 소비를 처리하지 않는 기존 플레이어 결정권 유지.
3. 사용자에게 사전에 고지되지 않은 자동 환생/자동 유물 개봉을 신규 구현하지 않음.
4. 실제 모바일 성능과 인간의 조작/재미는 이 수치만으로 검증할 수 없다. CI 통과와 모바일 실기 검증은 별개이며, main 배포/기존 세이브와 분리 유지.
