# 《네온 방치단》 자동 상자 개봉 효과 감사 및 플레이 기록 개선 (2026-11-18)

## 이번 작업의 결론
독립 탐사 원형의 유물 상자 자동 개봉은 사용자가 수동 수령을 반복하지 않도록 도와주는 **선택형 편의 기능**이다. 60초 자동 개봉을 켜면 보상을 먼저 얻는 경우가 있지만 RNG·구매 타이밍에 따른 결과는 복잡하며, **자동 개봉이 모든 시드에서 전진을 가속한다고 주장할 수 없다.**

자동 수집의 등장 자체로 첫 귀환 60분 밸런스가 완성된 것도 아니고, 25거리 조기 귀환이 지나치게 유리한 기존 문제도 완전히 해결되지 않았다. 이 회차에서는 전투/코어/유물 확률을 조정하지 않고, **측정의 재현성과 실제 사용자 기록의 신뢰성**을 우선 개선했다.

## 1. 동일 시드 비교: 96회 원정 (48쌍)
원형 엔진 `ExpeditionEngine.tick()`의 실제 로직으로 시드 12개 × 자동 구매 정책 2개(`balanced`, `adaptive`) × 첫 귀환 선택 2개(없음/25거리에서 한 번) × 유물 개봉 방식 2개를 실행.

- **자동 개봉 ON**: 유저가 도감에서 켰다고 가정. 60초마다 엔진이 이미 획득한 상자를 FIFO·최대20개로 개봉.
- **자동 개봉 OFF**: 유저가 5분마다 수동으로 상자 개봉. 25거리에서 수동 귀환한다면 그 직전에 쌓인 상자를 수동으로 개봉.
- 양쪽 모두 선택형 성장 자동 구매만 사용. 직접 터치 전투·강제 귀환·자동 코어 사용 없음. 첫 귀환 시 전선 코어 투자만 사용자가 직접 결정했다고 가정.
- 최종 45거리 격파 시 **남아 있는 상자도 개봉해 보유 유물 종류와 총 수령량 검증**. 이 마지막 개봉은 목표 격파 후 측정하므로 격파 시간에 영향을 주지 않는다.
- 두 방식의 **상자 획득 총량은 반드시 동일**(무귀환 9개/25거리 귀환 14개). 자동 쪽의 개봉 카운터는 귀환 시 초기화되므로 1차 원정 수치를 합쳐 실제 총 개봉 수를 확인한다.

| 45거리까지 전략 | 비교 쌍 | 자동 개봉이 빠른 경우 | 느린 경우 | 시간 차이 평균 |
|---|---:|---:|---:|---:|
| 귀환 없이 진행 | 24 | 11 | 13 | **+1.4%** (자동이 빠름) |
| 25거리 한 번 귀환·코어 투자 | 24 | 14 | 10 | **-0.7%** (자동이 느림) |

무귀환 조건의 빠름/느림 편차는 -18.8%~+15.2%였으며, 25거리 귀환 조건의 편차는 -14.0%~+10.2%였다. 이 시뮬레이션은 12개 고정 시드만 다뤘으며, 난수·선택 정책·수동 개봉 시간 가정에 따라 다른 결과가 가능하다. 자동 개봉의 **조작 부담 감소**라는 장점은 측정한 단축/지연 비율과 별개다.

`tests/expedition-auto-chest-impact-audit.cjs`를 생성하고 `tests/expedition-route-audit.cjs`에서 CI로 실행한다. 단일 조건에서 30% 이상 과도한 격차가 발생하면 이상치 경고를 띄우는 회귀 상한이 있으며, 이것이 바람직한 밸런스 수준이라는 뜻은 아니다.

## 2. 실제 플레이 기록에서의 문제와 수정
이전의 분단위 기록·귀환 요약·내보낸 JSON에는 자동 개봉 여부가 남지 않아, 상자를 직접 열었는지/자동 개봉했는지 알 수 없었다. 플레이 기록으로 후속 밸런스를 판단할 때 중요한 교란 변수였다.

- `site/expedition-engine.js`: 분단위 스냅샷에 `autoChestEnabled`와 `autoChestOpened`를 기록. offline/foreground 소스도 계속 구분. 최근 귀환 이력과 마지막 귀환 결과에 **해당 탐사 자동 개봉 개수**를 남긴다.
- `site/expedition-app.js`: 사용자가 직접 요청한 `neon-expedition-playtest-v1` JSON 내보내기에 `currentRun.autoChestEnabled`, `automaticChestsOpened`, `manuallyOpenedChests`를 넣는다. 스냅샷과 귀환 요약은 기존 포맷 필드 이름을 유지하면서 선택 필드를 확장한다. 자동 업로드 없음.
- `site/expedition-ui.js`: 도감의 탐사 기록에는 **이번 탐사 수동/자동 개봉 수**, 최근 귀환 상세에는 측정된 자동 개봉 수, 플레이 검증 요약에는 설정 상태를 표시. 전투/HUD에는 항목을 추가하지 않는다.
- **구 저장·구 플레이 기록 호환성**: 해당 자동 개봉 기록이 없는 과거 1분 로그 및 귀환 이력은 `null`(알 수 없음)로 복원. 과거에 실제로 사용하지 않았다는 증거가 없으므로 `false` 또는 0으로 거짓 단정하지 않는다. 최신 상태·자동 개봉 설정 자체는 기존의 기본 꺼짐 규칙을 유지.
- 자동 개봉 회차별 개수는 귀환할 때 0으로 초기화하지만 이전 회차 수치는 `runHistory`와 `latestReturn`에 저장하므로 사라지지 않는다.
